# Архитектура 0.1 — проект границы для независимого review

Новый автономный Node.js 24 ESM проект. Zod 4.6.7 — структурные и межполевые контракты; Playwright 1.63.0 — браузер. Версии зафиксированы lockfile. Нет импортов старых QA, серверов, БД или локальных конфигов. Сначала один процесс Control Plane и два дочерних процесса Browser/Verification через IPC; без брокера и микросервисной инфраструктуры.

Control Plane сохраняет snapshot сценария, операции, fixture и RunManifest ДО выдачи команды. Он владеет последовательным hash-chained журналом и артефактами. Browser Worker не выносит вердикт. Verification Worker получает пути к неизменяемым артефактам, сам читает их, проверяет хеши, цепочку, run/manifest/fixture/step/entity и сам выполняет GET через разрешённый адаптер. Процессное разделение защищает от случайной общей логики, но не является защитой от злоумышленника с доступом к диску.

Первый адаптер — только контролируемый localhost стенд с уникальной записью и независимым GET по fixtureId. Не называть его CIZ Adapter. Неподдерживаемые операции отклонять. До готовности полного adapter нельзя запускать произвольную внешнюю цель. Секреты передавать по credential refs, не в snapshot. Сохранение HTTP только через allowlist полей; headers/cookies/пароли не сохранять. DOM и screenshot production требуют отдельной политики маскирования.

Мутация: durable intent → однократная отправка → response либо неизвестность → read-only reconciliation. Intent без ответа после рестарта означает «возможно отправлено»; повтор запрещён. В 0.1 даже доказанное отсутствие не разрешает автоматический повтор: нужен новый утверждённый прогон. Потерянный response оставляет INCONCLUSIVE, хотя независимое чтение может обнаружить объект; обязательная цепочка доказательств не подделывается.

Детерминированное исполнение без модели. maxModelCalls=0. Неограниченные циклы/неявные retries запрещены. Отмена закрывает браузер; начавшаяся мутация не откатывается и не повторяется. Каждая попытка наблюдения ограничена общим deadline. Worker crash и рестарт ведут к reconciliation, никогда к blind replay. Один активный прогон на fixture/environment; durable эксклюзивная блокировка, stale lock восстанавливается только через reconciliation.

0.1 поддерживает ровно одну бизнес-мутацию и линейную цепочку действий с финальным verify. Это начальная способность, не сокращение 1.0. Новые OP-A…OP-F и DAG добавляются после принятого ядра через версию контрактов. Acceptance получает только APPROVED; exploration создаёт DRAFT с source/runtime provenance. Исходный текст хранится отдельно.

Контракты: packages/contracts/index.mjs + экспорт schemas/*.schema.json. JSON Schema проверяет структуру; validate() дополнительно межполевые правила. Междокументные ссылки, hashes, полнота effect IDs и независимость источника проверяются runtime/verifier. Структурно валидный verdict не является достаточным доказательством PASS.

Хеширование: SHA-256 от канонического JSON (объектные ключи отсортированы рекурсивно, порядок массивов сохранён). Scenario approval hash считается от всего документа без поля approval, со status=APPROVED. Snapshot hash сценария включает approval. Evidence checksum — raw UTF-8 bytes артефакта; hash цепочки — канонический envelope. Локальная цепочка обнаруживает случайное/частичное изменение, но не доказывает подлинность против полной перезаписи владельцем диска; подписанный внешний anchor — отдельное усиление.

Приоритеты: корректность → надёжность → доказуемость → скорость → экономичность. Версия 0.1 не принята без реальной безопасной бизнес-операции ЦИЗ. Версия 1.0 не принята без диагностики исходного пункта 7, утверждения исправления и полного доказанного 23-шагового прогона.
