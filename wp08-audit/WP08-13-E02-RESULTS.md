# WP08-13 — ЭТАП II: НЕЗАВИСИМЫЕ АТАКИ E-02

Цель — проверить инварианты вне набора Luna; действия атак написаны аудитором, обвязка мира
(`_w2.mjs`: стенд, trust root, approval) переиспользована. Код продукта не менялся, SHA 1a510a5.

Результат: **7/7 сценариев PASS** (лог `evidence/stage2/e02.log`, сценарии `repro/e02-suite.mjs`).
Три итерации потребовались из-за ошибок самого аудиторского harness, не из-за продукта.

| ID | Атака | Проверка | Итог |
|---|---|---|---|
| E02-01 | Повреждение анкера после PASS | `observeTrusted` не выдаёт PASS; после восстановления анкера PASS возвращается | PASS |
| E02-02 | Два одновременных trusted-run на одном bundle/approval | ≤1 PASS, ≤1 POST, второй запуск — отказ, наблюдение не даёт PASS | PASS |
| E02-03 | Подмена `readSetSha256` в verification-записи после PASS | reconcile отказывает, PASS не подтверждается, повторного POST нет | PASS |
| E02-04 | Повреждённый `trust/trusted-run.json` (sidecar) | generic API отказывает (INTEGRITY_ERROR), обход доверенного входа невозможен | PASS |
| E02-05 | Усечение `evidence.jsonl` (нарушение порядка durable-записей) | `observeTrusted` не выдаёт PASS, evidence-commits присутствуют | PASS |
| E02-06 | Удалённая verification-запись в Trust Root при recovery | reconcile отказывает, PASS не восстанавливается, POST не повторяется | PASS |
| E02-07 | Повтор IPC-подписи для использованного anchorId | второй анкер не создан, повтор отклонён/идемпотентен, verdict ровно один | PASS |

## Ограничения

- Обвязка мира заимствована (`makeWorld`), поэтому сценарии не полностью независимы от фикстур проекта.
  Действия атак (мутации durable-состояния, Trust Root, sidecar, evidence, IPC) — собственные.
- E02-01/E02-04 фиксируют штатное поведение: sidecar и анкер не являются «доказательством PASS»,
  они защищают входы; это проверено как отсутствие обходного пути, а не как дефект.

## Ревизия 2 (после замечаний владельца)

1. **E02-07 усилен.** Replay выполняется с **изменённой** аттестацией (`candidateSha256` заменён) для уже
   использованного `anchorId`. Ожидание — явный `ANCHOR_BINDING_REJECTED`; проверено: второй анкер
   не создан, ровно один verdict. Топология: pipe — приватный канал Control↔anchor-signer; попытка
   подключения извне — **вне модели A1–A3**, это зафиксировано; инвариант проверен строго, границы
   доверия не обходятся.
2. **E02-04 разделяет гарантии.** Generic API после повреждения `trust/trusted-run.json` —
   `INTEGRITY_ERROR` (fail-closed). `observeTrusted` при этом возвращает PASS, но только с
   `anchorStatus = ANCHOR_OK`; sidecar не является доказательством происхождения и не влияет
   на trusted evidence. Зафиксировано как штатное разделение, а не как дефект.
3. **E02-06 дополнен.** После удаления verification-записи проверяются: отказ `reconcileTrusted`,
   отсутствие неподтверждённого PASS у `observeTrusted` и отсутствие второго POST.
4. **Переносимость.** Жёсткие пути удалены: цель задаётся `--target`, ревизия — `--sha`; suite
   сам проверяет `HEAD == sha` и чистоту worktree и завершается с кодом 2 при несоответствии.

Повторный прогон на продуктовом SHA `1a510a5d5929534d400dc965f58c78cf468bc270`: **7/7 PASS**,
все сценарии записали `head=1a510a5…, dirty=false`.
