# WP08-14 — F-06: STABLE 0.1, ПЕРВОПРИЧИНА НЕСТАБИЛЬНОСТИ

## Факты

| Прогон | Результат |
|---|---|
| Полный `npm test` на теге `v0.1.0-stable` (88fc1d7), запуск 1 | 58/59, упал `WP-A: удаление locks и leases…` |
| Полный `npm test`, запуск 2 | 58/59, упал `очистка чужого объекта отклоняется без удаления` (PASS ожидался, получен INCONCLUSIVE) |
| Изолированные повторы | locks: 3/3, затем 1 fail / 5, затем 10/10 PASS; cleanup: 1 fail / 3, затем 0 fail / 5 |

Рабочее дерево стабильного тега чистое, remediation на него не влияет (разные ветки).
Гейт запускается последовательно (`--test-concurrency=1`), т.е. падение не вызвано параллелизмом файлов.

## Что удалось доказать

1. **locks/leases** — недетерминированный тест исторической версии: он удаляет lock/lease-файлы
   в окне между `waitUntil(mutationCount === 1)` и стартом второго прогона и ожидает BLOCKED.
   При опережении первого прогона окно закрывается; воспроизведение 1/5, затем 10/10 PASS.
2. **cleanup тест** — единственное падение 1/3, дальше 0/5; причина не установлена.
3. Оба падения — в **исторических тестах версии 0.1**, при неизменном теге и без правок remediation.

## Что не доказано

Точная первопричина (гонка в самом тесте, таймаут браузера/Verification под нагрузкой либо иное)
для второго сценария не установлена. Называть её «доказанной» нельзя.

## Классификация и предложение

- F-06 = **UNVERIFIABLE**, не PASS и не FAIL продукта 0.2.
- Первопричина, вероятнее всего, в недетерминированном дизайне исторических тестов; для решения
  владельца предлагается отдельное исключение F-06 из критериев выпуска 0.2 с фиксацией этого текста,
  либо требование стабильного прогона на выделенной среде. Переименование UNVERIFIABLE→PASS недопустимо.
