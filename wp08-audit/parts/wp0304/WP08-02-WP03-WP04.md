## 2. Проверенные компоненты

### 2.1 `packages/trust/policy.mjs` — PDP (WP-03)

- **Ответственность.** Чистая функция `decide(facts) → TrustDecision` (11 полей §5.3) и `projectToVerdict(decision)`. Решение только по заранее собранным фактам.
- **Контракт.** `docs/wp-00/03-CONTRACT-PROPOSALS.md:104-168` (TrustDecision, коды, проекция), §5.3 baseline.
- **Входы/выходы.** Вход — строгая форма `facts` (`policy.mjs:100-150`); выход — `{decisionId, effect, phase, reasonCode, approvalId, inputsHash, environmentId, environmentGeneration, authenticatedSid, obligations, evaluatedAt}`.
- **Граница доверия.** PDP **не проверяет подписи approval/отзыва, аттестацию и consumption** — это обязанность сборщика фактов (`WP-03-REPORT.md:183`, P-02). Мой тест «ГРАНИЦА»: при вручную собранных facts с заведомо недействительной подписью approval (`ff…`) и аттестацией без `challenge`/`pid` PDP возвращает `ALLOW TRUST_OK` (`01-pdp.log`). Через публичный доверенный вход такие facts не проходят (05-injection).
- **Чистота.** Статически: импорты только `node:crypto` (`randomUUID`) и `core/canonical.mjs`; нет `fs/net/http/https/tls/child_process`, `fetch`, `execFile`, подписи/генерации ключей. Динамически: `decide` работает при заглушенных `fs.*`, `net.connect`, `http.*`, `globalThis.fetch`. Единственная недетерминированность — `decisionId` (принятое исключение, `WP-03-REPORT.md:144-147`).
- **Обработка ошибок.** Неожидаемая ошибка формы → `DENY CONTRACT_INVALID` без TypeError (`policy.mjs:384-397`); неизвестные коды сборщика → `CONTRACT_INVALID` во всех фазах.
- **Скрытые side effects.** Нет; facts не мутируются.
- **Соответствие WP-00.** Порядок и reasonCode соответствуют `WP-03-REPORT.md:56-84`; проверено матрицей 40+ мутаций.
- **Дефекты.** F-WP03-01 (граница PDP, P3), F-WP03-02 (мёртвая ветка проекции, P3), F-WP03-03 (чтения не исполняются, P3).

### 2.2 `packages/trust/facts.mjs` — сборщик фактов

- **Ответственность.** Превращает результаты проверок identity/approval/environment в форму facts; ошибки чтения не бросает, а кладёт кодом в `*.error` (`facts.mjs:5-7,28-62`).
- **Граница доверия.** Здесь выполняются криптопроверки: `principalFact→verifyAndAssertPrincipal`, `approvalFact→readApprovalState` (подпись owner, закреплённый документ, bindings, отзыв, consumption), `environmentFact→loadEnvironmentRecord` (подпись owner, поколение, отзыв, сверка origin/generation).
- **Проверено независимо.** Подсунуть approval мимо верификации нельзя: (a) изменённый подписанный документ → `BLOCKED`, POST=0; (b) незакреплённый документ (`signApproval` без commit) → `BLOCKED`, POST=0; (c) approval чужого trust root → `BLOCKED`, POST=0; контрольный валидный approval → preflight allow (`05-injection.log`).
- **Дефект.** `environmentFact` (`facts.mjs:53-62`) не использует `credentialRef`; `expected` не содержит credential-связки → E-04 не закрывается на уровне PDP (F-WP04-02).

### 2.3 `packages/trust/environment.mjs` — реестр сред и аттестация (WP-04)

- **Ответственность.** Поколенческий реестр `trustRoot/environments/<id>/<generation>.json` (CREATE_NEW + fsync + перечитывание), подпись/проверка записи owner-ключом, challenge-response аттестация ключом стенда, liveness (PID + единственный владелец порта).
- **Контракт.** 12 полей записи §5.1, 10 полей аттестации; `kind ∈ {local-stand,dev,production}`; origin local-stand строго `http://127.0.0.1:<port>/`; коды §5.1.
- **Граница доверия.** Запись проверяется подписью owner из trust root; аттестация — ключом стенда, `keyId` которого обязан совпасть с `standKeyId` owner-подписанной записи. Публичный ключ стенда в trust root не хранится и передаётся явно (R-08).
- **Обработка ошибок.** `ENVIRONMENT_UNKNOWN/REVOKED/KIND_DENIED/ATTESTATION_FAILED/UNAVAILABLE/CONTRACT_INVALID`; редиректы запрещены, ответ >64 KiB отвергается потоково (D-04), timeout 2000 мс; при неизвестном ключе — отказ, не пропуск.
- **Подтверждено независимо (`02-environment.log`, 8/8, exit 0):**
  - E-01: свежий challenge на каждую проверку; перехваченная аттестация не переигрывается (новый challenge → `ENVIRONMENT_ATTESTATION_FAILED`); зеркало без ключа стенда → отказ; мутаций 0.
  - E-07 (до dispatch): после остановки стенда и занятия порта rogue-процессом `attestLiveEnvironment` → `ENVIRONMENT_ATTESTATION_FAILED`, rogue POST=0; `processAlive`/`portOwnerPid` работают (не-loopback → null).
  - E-08: монопольный bind — второй `serveLocalFixture` и rogue на том же порту → `EADDRINUSE`.
  - E-06: `kind=dev/production` → `ENVIRONMENT_KIND_DENIED` **до любого соединения** (`fetchImpl` не вызван ни разу).
  - Подпись записи: неподписанная/подменённая/чужая-owner запись → `CONTRACT_INVALID`/`APPROVAL_SIGNATURE_INVALID`; поколение назад → `CONTRACT_INVALID`; `revoked` → `ENVIRONMENT_REVOKED`; битая запись → `CONTRACT_INVALID` (fail-closed).
  - R-08: аттестация чужим ключом → отказ; self-signed ключ проходит только при owner-записи с его `standKeyId`; без явного `standPublicKey` — отказ. R-08 подтверждён как принятая граница.
- **Дефекты.** F-WP04-01 (P3), F-WP04-02 (P2), F-WP04-03 (P0).

- **Ответственность.** Фикстура 0.1 (страница формы, `GET /environment`, `GET/POST /records` с Bearer и idempotency-key) + аддитивно `POST /attest` с подписью Ed25519 ключом, живущим только в памяти.
