## 1. Общий статус

# REJECT

Найдены **два независимо воспроизведённых P0-дефекта класса «ложный доверенный PASS»**:

1. **AUD-P0-01 (R-07):** процесс того же Windows SID, не имеющий ключа owner, при наличии выписанного owner-approval, genuine consumption и доступа к named pipe подписанта сам создаёт подложную цепочку evidence + PASS-candidate, получает **валидный анкер** от настоящего `anchor-signer` и публикует terminal PASS; публичный `observeTrusted` возвращает `trusted:true passed:true verdict:PASS` без реальной мутации и без Verification.
2. **AUD-P0-02 (R-03 → эскалация):** после последней аттестации T-C (и даже после POST) настоящий стенд гасится, его порт занимает подставной процесс; `apps/verification/worker.mjs` **не аттестует среду** (доверяет публичным `GET /environment` и `GET /records`), поэтому rogue возвращает «правильные» записи → Verification PASS → анкер → **доверенный PASS**. В сценарии B реальная мутация вообще не выполнялась (`mutationCount=0`), Bearer стенда утёк rogue. Окно T-C→POST измерено ~35 мс (attest→POST ~147 мс), подмена порта выполнена за 3 мс — это не «микроскопический» остаток.

Оба дефекта опровергают ключевой критерий миссии: **безопасный доверенный маршрут от подписанного разрешения до единственного достоверного бизнес-результата не доказан**; доверенный PASS достижим без достоверной бизнес-операции.

## 4. Тестовая инфраструктура

Независимо подтверждены числа обязательных прогонов (кроме первого W2-прогона), но найдены слабости доказательности: redteam не входит в `npm test`; `races` выбирается по хрупкому `--test-name-pattern` без guard-а на количество; агрегаторы redteam выводят PASS из exit code при нераспарсенном JSON; матрица присваивает строке PASS по общему вердикту скрипта, покрывающего несколько строк; часть проверок тавтологична; волна-1 скрипты жёстко привязаны к базе `0e7e6c2` и на HEAD заведомо ложны (в гейтах не запускаются). Ни один из найденных P0 не покрыт 24 атаками Red Team: их false-pass-сценарий использовал подделку цепочки **без** approval/consumption/анкера и потому не проверял R-07; подмена среды проверялась только до POST, не после T-C/после POST.
