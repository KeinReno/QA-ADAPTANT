# 05 — KNOWN RISKS (KAIDEN QA ADAPTANT 0.2)

Классификация: P0 — ложный PASS/вторая мутация/второй verdict; P1 — обход разрешения или утечка секрета;
P2 — ограничение с эксплуатационным следствием; P3 — наблюдение. Открытых P0 нет.

| ID | Риск | Severity | Состояние | Влияние | Что сделано |
|---|---|---|---|---|---|
| R-01 | Осиротевшая блокировка `trust-root/guards/<approvalId>.lock` после SIGKILL владельца | P2 | принят, fail-closed | последующие revoke/consume по этому approval отказывают через ~5 с; второго ACK/POST и расхода нет | tests/trust-r01.test.mjs: fail-closed, ручное восстановление только после доказанной остановки; авто-удаление запрещено (открывает окно второго dispatch) |
| R-02 | keygen мог создавать секреты внутри каталога прогонов | P2 | устранён | секреты в runDir | keygen.mjs отвергает пути с сегментом runs; тесты R-02 в tests/trust-keygen.test.mjs |
| R-03 | Остаточная гонка: стенд погибает между последней проверкой процесса и отправкой уже разрешённого пакета | P2 | принят как граница | мутация может уйти на сокет, занятый другим процессом, в микроскопическом окне | T-C сужает окно; повтор POST не выполняется |
| R-04 | DPAPI/ACL одного Windows SID не отделяют Control/подписанта от другого кода той же учётной записи | P2 | принят как граница локальной 0.2 | код под тем же SID может получить ключ и собрать связку | явно зафиксировано в docs/changes/006; для Dev/ЦИЗ границу нужно выносить |
| R-05 | `trust-root/profile.json` (anchorBudgetMs) не подписан криптографически | P2 | принят | подмена файла меняет длительность ожидания анкера | диапазон 1…60000, default 5000, вызывающий не меняет; PASS без анкера невозможен |
| R-06 | Named pipe подписанта не сужает ACL сверх текущего пользователя | P2 | принят (R-04) | любой процесс того же SID может обратиться к подписанту | подписант проверяет связку сам, хеш от вызывающего не принимает |
| R-07 | Подписант не пересчитывает бизнес-checks candidate | P2 | принят (docs/changes/006) | подложный candidate с валидной связкой может быть подписан | candidate строится только из Verification в WP-06; PASS отдаёт только observeTrustedVerdict |
| R-08 | Публичный ключ стенда передаётся в доверенный вход из регистрации (не персистится в trust root) | P3 | принят | подделка ключа не проходит сверку standKeyId и подписи | W-01 WP-04; вынос в доверенный реестр — отдельное изменение |
| R-09 | Поколение среды в PDP для фаз чтения не сверяется | P3 | принято (docs/changes/007) | чтение связано с approval, а не с живой аттестацией | строгий отказ по статусу и виду среды |

## Ограничения доказательства

Все результаты получены на одной локальной Windows-машине с изолированным стендом 127.0.0.1.
Это не доказывает поведение против ЦИЗ/Dev, другого пользователя Windows или машины, где противник
управляет ключом owner или всем каталогом прогона. Внешняя приёмка (WP-08) остаётся за владельцем.
