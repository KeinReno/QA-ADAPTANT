# 04 — модель угроз

Граница расчёта: один локальный компьютер, один Control Plane, каталог прогонов и отдельный trust root. Противник не является держателем приватного ключа `owner`, пока явно не назван сценарий компрометации ключа. Процессное разделение Browser и Verification защищает от случайной общей логики и не считается границей от того, кто управляет диском.

## Доверенные базы

| База | Доверяем | Не доверяем |
|---|---|---|
| Приватный ключ owner вне репозитория | Подпись approval, реестра и анкера | Копии в чатах, снимках, evidence |
| Публичный ключ в trust root | Проверка подписи | Файл, подменённый без смены ожидаемого keyId у процесса |
| Код Control на ревизии, которую принял отдельный аудит | PEP не обходится процессом Browser | Запуск изменённого Control без приёмки |
| Каталог прогона | Рабочие снимки и локальная цепочка | Подлинность против полной перезаписи |
| Ответ `/environment` сам по себе | Ничего, пока не совпал с подписанным реестром и nonce | Строку fingerprint |
| Слова модели и HTTP 200 | Ничего | Уже зафиксировано в правилах проекта |

Ожидаемый `keyId` процесс получает при старте из `owner.pub`, прочитанного один раз, и держит в памяти. Подмена `owner.pub` после старта не меняет уже загруженный ключ. Подмена до старта — компрометация корня: все новые подписи этого ключа считаются ключом злоумышленника. Это принимаемый остаточный риск одного локального ключа. Обнаружение такой подмены не обещается средствами 0.2. Защита — права на файл ключа и отсутствие ключа в репозитории.

## Секреты

| Секрет | Где живёт | Куда не попадает |
|---|---|---|
| Приватный ключ Ed25519 | Файл `QA_ADAPTANT_TRUST_KEY` | Git, snapshot, evidence, анкер, ответ CLI, журнал событий |
| Attestation nonce | Память стенда и память Control на время сверки. На диске только хеш | Evidence, approval |
| Bearer стенда | Память стенда и окружение дочернего процесса после разрешения PEP | Snapshot, evidence, документы |
| Старые сессии ЦИЗ | Нигде в этом проекте | Не копируются |

Утрата приватного ключа останавливает новые approval и новые анкеры. Уже записанный терминальный verdict 0.1 без возможности проверить подпись в доверенном режиме не показывается как PASS.

## Участники и что им запрещено

| Участник | Допустимо | Обход, который закрываем |
|---|---|---|
| Владелец ключа | Подпись и отзыв | Подпись не равна записи intent |
| Оператор | Запрос старта | Подмена входов после подписи |
| Control (`runner`) | PEP, расход, запись evidence | Второй POST, PASS без анкера |
| Browser | Щелчок после ACK, один POST на allowlist | Прямой POST до ACK, чужой origin, второй POST |
| Verification | GET и бизнес-вердикт | Публикация PASS доверенного режима, чтение чужого тела как независимого |
| Agent | Ничего в 0.2 | Вызов адаптера и выбор «разрешённого Dev» |
| Вызывающий `start()` | Старый локальный путь | Объявление произвольного loopback средой доверенного пути |

## Сценарии обхода

| Угроза | Что мешает |
|---|---|
| Подменить входы после подписи | `approvedInputsHash` в подписи и повторная сверка замороженного снимка на T-B и на теле POST |
| Подменить операцию или версию | Оба поля в подписи, плюс действующий реестр смыслов 0.1 |
| Подменить среду | Реестр и поколение в подписи, живой nonce, буквальный `127.0.0.1` |
| Повторить approval на другом `runId` | Эксклюзивный consumption |
| Повторить approval на том же `runId` после краха | Идемпотентность 0.1 и запрет второго ACK с новым payload |
| Использовать чужой Principal | `subjectPrincipalId` и роль в PDP |
| Просрочить или отозвать | Состояние вне подписи, проверяется на каждом T-B |
| Согласованно переписать каталог прогона | Подпись анкера другим каталогом и ключом. Без ключа новый PASS не собирается |
| Подменить только локальный verdict | Анкер указывает `envelopeSha256` терминального коммита |
| Выдать секрет Browser заранее и увести его на другой порт | На доверенном пути секрет мутации выдаётся после T-B и только для origin реестра. Browser дополнительно режет origin |
| Обойти Policy прямым HTTP адаптера | Адаптера в 0.2 нет. Контракт: нет `DispatchPermit` — нет вызова. Модуль адаптера не импортируется Browser и Intelligence |
| Гонка двух START за один approval | Эксклюзивное создание consumption. Второй получает `APPROVAL_REPLAY` или `APPROVAL_CONSUMED` |
| Потеря trust root в середине прогона | Новый dispatch — INDETERMINATE и BLOCKED. Уже записанный intent не переотправляется. PASS не публикуется |
| Редирект или смена DNS | Для 0.2 DNS нет. Редирект запрещён. Смена порта меняет origin и не совпадает с реестром |
| Сменить адрес между проверкой и POST | T-B повторяет аттестацию непосредственно перед ACK. Несовпадение поколения — отказ, intent не пишется. Если intent уже был, POST не повторяется |
| Компрометация приватного ключа | Вне модели обнаружения 0.2. Реакция владельца — прекратить использовать корень и не принимать новые анкеры этого keyId. Ротация ключа отложена |

Полная перезапись и каталога прогона, и trust root, и подмена ключа в памяти процесса одним противником с правами владельца машины не различается с действиями настоящего владельца. 0.2 это не обещает закрыть.

## Отрицательные результаты, которые нельзя смягчать

- INDETERMINATE на новой мутации не превращается в ALLOW.
- Отсутствие анкера не превращается в PASS.
- Расход approval не снимается, чтобы «безопасно повторить POST».
- Совпадение fingerprint не заменяет nonce и поколение.
- Вердикт Verification Worker со значением PASS не публикуется доверенным API, пока T-D не принял анкер.
- Недоступность ЦИЗ, Dev или внешнего якорного сервиса в 0.2 нечем заменить: внешнего сервиса нет, локальный стенд обязан быть доступен, иначе отказ.
