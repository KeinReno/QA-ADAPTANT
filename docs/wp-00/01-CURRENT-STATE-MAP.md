# 01 — карта ядра 0.1

Проверено по дереву на `88fc1d7b46e898b9d1ac85996042798fe55a2619`, тег `v0.1.0-stable`, ветка до документов WP-00 была `master`, рабочее дерево было чистым. Утверждения ниже сверены с кодом, а не только с отчётами.

## Что в репозитории есть

Принятые документы на месте: `ARCHITECTURE.md`, `MODULE-BOUNDARIES.md`, `HANDOFF.md`, `ACCEPTANCE-REPORT.md`, `INDEPENDENT-STABLE-GATE-06.md`, `docs/releases/0.1.0-stable.md`, `docs/ci-test-mode.md`, шесть корневых контрактов, `packages/contracts/index.mjs`, `schemas/*.schema.json`, `docs/contract-freeze.json`.

Замороженный набор `docs/contract-freeze.json` включает контракты и `ARCHITECTURE.md`. Их хеши менять в 0.2 нельзя. Новые решения записываются только в `docs/wp-00/` и будущие `docs/changes/`.

## Процессы и владение

Один процесс Control Plane. Browser Worker и Verification Worker — дочерние процессы, IPC `{type, commandId, runId, payload}`. Брокера и базы нет. Зависимости runtime: `zod` 4.6.7 и `playwright` 1.63.0.

| Модуль | Факт по коду | Что уже можно использовать в 0.2 |
|---|---|---|
| `packages/contracts` | `schemaVersion` буквально `0.1.0`. Enum reason и kind evidence закрыты | Не расширять. Новые объекты версионировать отдельно |

| `packages/core/store.mjs` | Снимки, append-only `evidence.jsonl`, коммиты `evidence-commits/NNNNNN.json` через temp+fsync+rename | Локальная целостность. Не корень доверия |

## Как сейчас принимается мутация

Порядок в `run()`:

1. Валидация контрактов 0.1 и запись снимка до сети.
2. `assertApprovedOperation` — идентификатор операции, имя актора, набор ключей входов, обязательность эффектов и равенство `equals` значению входа.
3. Привязка fixture и lease.
4. GET `/environment`. Совпадают `environmentId` и `fingerprint` с полями манифеста, которые задала вызывающая сторона.
5. Browser получает `QA_ADAPTANT_FIXTURE_TOKEN` уже при старте процесса, до щелчка.
6. Перед щелчком Browser шлёт `INTENT`. Control пишет `mutation-intent` и отвечает `ACK`.
7. Повтор того же `intentId` возвращает прежний ACK. Другой payload — `INTEGRITY_ERROR`.
8. Фактический POST не уходит в сеть, пока Control не подтвердил тело и не прислал `EVIDENCE_ACK`.
9. Повторный POST на `/records` обрывается в Browser.
10. После durable intent потеря worker ведёт в reconciliation, не в новый POST.
11. Терминальный verdict один. Повторный START с тем же `runId` и тем же снимком не исполняет действия заново.

Это и есть рабочие точки расширения. Новая проверка должна встать в Control **до** `appendEvidence(... mutation-intent)` и **до** ACK. Вторая проверка тела POST уже есть и остаётся защитой от расхождения с замороженным снимком.

## Что утверждение 0.1 реально покрывает

`scenario.approval` — это `{actor, approvedAt, contentSha256}`. `contentSha256` равен `scenarioApprovalHash`: канонический хеш сценария со `status=APPROVED` и без поля `approval`. Подписи ключом нет. Любой, кто собирает bundle, может проставить актора `local-test-harness` и верный хеш.

Реестр не ограничивает **значения** `title`, `executorId` и `comment`. Он требует, чтобы ожидаемый эффект равнялся тому значению, которое уже лежит во входах. Вызывающая сторона выбирает оба.

`fixture.authorization` — строка актора, scope и время. Control эту подпись не проверяет: поля нет. `credentialRef` в локальном bundle — `local:none`. Секрет стенда живёт в памяти сервера и в окружении дочернего процесса, в снимок не пишется. Это свойство нужно сохранить.

`operation.roles` сравниваются со строками `fixture.accounts[].role`. Это не аутентификация человека.

## Идентичность среды, как она есть

`RunProtocol` принимает только `http://127.0.0.1:<порт>/`. Это отсекает произвольный внешний URL и не отсекает другой процесс на loopback.

Fingerprint локального стенда — SHA-256 константы `qa-adaptant-local-fixture-v1`. `environmentId` — случайный UUID, который harness кладёт в манифест и который стенд отдаёт в `/environment`. Совпадение этих двух строк доказывает только то, что ответ сервера совпал с текстом манифеста. Вызывающая сторона может поднять свой HTTP-сервер на `127.0.0.1` и повторить обе строки. Для принятого тестового режима harness создаёт сервер сам, поэтому тесты 0.1 честные. Для внешнего вызова `start()` этой проверки мало.

`RUN-PROTOCOL.md` прямо говорит: строка fingerprint не обещает обнаружить любой backend. Архитектура 0.1 также говорит, что цепочка хешей не защищает от полной перезаписи каталога владельцем диска.

## Коды, которые уже есть и которых нет

В `reasonCodes` есть `AUTH_UNAVAILABLE`, но Control не использует его как результат проверки личности. Остальные коды закрывают контракт, среду, целостность, отмену и потерю worker.

Новый точный код в этот enum не добавляется. Иначе меняется замороженная схема. Точные причины доверия живут в объекте `TrustDecision` версии 0.2. Наружу, в verdict 0.1, они проецируются только существующими кодами. Таблица проекции — в контрактах.

## Пробелы относительно внешних мутаций

| Пробел | Следствие |
|---|---|
| Нет Principal и ключа | Нельзя отличить владельца от вызывающего кода |
| Approval не связывает значения | Подмена `title` до старта остаётся «утверждённой» операцией |
| Approval не одноразовый и не отзывается | Один и тот же документ можно приложить к другому запуску |
| Среда подтверждается эхом манифеста | Чужой loopback можно назвать стендом |
| Токен стенда выдаётся Browser до разрешения мутации | Секрет доступен процессу раньше решения Policy |
| Анкер в том же каталоге данных снят и не заменён внешним | Согласованная перезапись журнала, коммитов и событий не обнаруживается |
| Verification решает бизнес-эффект, но не подлинность разрешения | PASS возможен без утверждения конкретных входов человеком |
| Прямой будущий адаптер не имеет затвора | Если ЦИЗ-клиент вызовет HTTP сам, текущий затвор Browser его не увидит |

Последний пункт сейчас не эксплуатируется: каталога `adapters/ciz` нет, `start()` ходит в цель только через Browser. Дыру нужно закрыть контрактом границы до появления адаптера.

## Что сознательно не переписывается

Не меняются: формат коммитов evidence, правило одной мутации, запрет слепого повтора, lease и привязка fixture, реестр `local-create-record`, обязательные команды `npm test`, `npm run test:races`, `npm run schemas`. Остаточный P3 — единичный fail-closed `INCONCLUSIVE` при шести конкурентных OBSERVE — остаётся регрессионным наблюдением, не поводом трогать журнал.

## Точки подключения Trust Layer

| Точка | Момент | Решение |
|---|---|---|
| T-A | После заморозки снимка, до запуска Browser | Отказ без процесса Chromium и без выдачи секрета |
| T-B | В обработчике `INTENT`, до записи `mutation-intent` и до ACK | Единственное разрешение мутации |
| T-C | В обработчике `HTTP_REQUEST`, существующая сверка тела | Остаётся. Не заменяется Policy |
| T-D | Перед записью verdict `PASS` | PASS только при сверенном анкере |
| T-E | `observe` / `reconcile` доверенного прогона | Чтение не расходует право мутации; PASS не показывается без анкера |
| T-F | Будущий адаптер | Вызов только из Control и только с `DispatchPermit` |

T-B — обязательная точка. Проверка только в форме или в CLI считается обходом.
