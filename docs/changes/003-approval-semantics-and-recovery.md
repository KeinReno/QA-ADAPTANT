# CR-003 — семантика утверждённых эффектов и видимость журнала

Схемы 0.1.0 не меняются. Это уточнение после REJECT RC2. Исполнитель не принимает результат.

Доверенный реестр локального ядра фиксирует не только идентификаторы эффектов, но и их смысл: `required=true`, отсутствие `appliesWhen`, `equals` равно соответствующему `inputs[field]`, набор входов ровно `title`, `executorId`, `comment`. Проверка повторяется перед выдачей уже записанного PASS или FAIL. Реестр по-прежнему не аутентифицирует владельца и не авторизует операции ЦИЗ.

`evidence-anchor.json` хранит `byteLength` зафиксированного префикса. Читатель видит только этот префикс. Байты, дописанные после анкера, не считаются повреждением и не входят в журнал, пока анкер не обновлён. Анкер защищает от одиночной и частичной подмены. Согласованная правка `evidence.jsonl`, `evidence-anchor.json` и `events.jsonl` в том же каталоге остаётся границей каталога данных: локальный анкер её не закрывает.

Неполный каталог прогона без доказанной мутации сохраняется в `quarantine/` и может быть начат заново. Нечитаемый или усечённый журнал, по которому нельзя доказать отсутствие мутации, даёт `INCOMPLETE_RUN` и не запускает повторную мутацию.

Привязка fixture публикуется переименованием каталога, в котором `bind.json` уже записан. Каталог без `bind.json` и привязка прогона без durable intent освобождаются. Привязка прогона, где мутация уже могла быть отправлена, не снимается.

Ответ HTTP 200 на уже существующий объект не является доказательством создания. Для PASS этой операции нужен ответ 201.

Идентификация browser при cancel сверяет случайный nonce аргумента процесса, а не подстроку пути прогона.
