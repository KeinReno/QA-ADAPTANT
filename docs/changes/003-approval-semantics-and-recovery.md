# CR-003 — семантика утверждённых эффектов и видимость журнала

Схемы 0.1.0 не меняются. Это уточнение после REJECT RC2. Исполнитель не принимает результат.

Доверенный реестр локального ядра фиксирует не только идентификаторы эффектов, но и их смысл: `required=true`, отсутствие `appliesWhen`, `equals` равно соответствующему `inputs[field]`, набор входов ровно `title`, `executorId`, `comment`. Проверка повторяется перед выдачей уже записанного PASS или FAIL. Реестр по-прежнему не аутентифицирует владельца и не авторизует операции ЦИЗ.

`evidence-anchor.json` больше не создаётся: источник истины — каталог коммитов. Чужой хвост не подтверждается, если его `runId`, хеш манифеста, `fixtureId` или `stepId` не совпадают со снимком, либо если он повторяет уже подтверждённый intent, request, response или verdict. Артефакт, который записан, но не входит в подтверждённый журнал, переносится в `quarantine/` этого прогона, и запись продолжается без повторной мутации. Сообщение `WORKER_LOST` содержит код выхода, сигнал и фазу.

Журнал `evidence.jsonl` только дописывается. Каждый коммит сначала записывается во временный файл, который не входит в набор подтверждённых имён, и только после fsync переименовывается в новый `evidence-commits/NNNNNN.json`. Существующий коммит этим переименованием не заменяется. Читатель принимает только непрерывную цепочку с первой позиции: пропуск, обрезанный JSON или несовпадение номера останавливают цепочку, и более поздние файлы не читаются. Хвост после последнего целого коммита не является записью. Писатель подтверждает ровно один целый следующий конверт только после проверки канонического хеша, артефакта и родителей. Если события уже называют терминальный результат, такой хвост подтверждается только когда это вердикт с тем же значением. Иначе журнал не продолжается. Откат терминального коммита даёт `INTEGRITY_ERROR` для OBSERVE, START и RECONCILE. Отсутствующий артефакт даёт `INTEGRITY_ERROR`, а не сырой `ENOENT`.

Анкер в том же каталоге защищает от одиночной и частичной подмены. Согласованная правка журнала, коммитов и `events.jsonl` остаётся границей каталога данных.

Неполный каталог прогона без доказанной мутации сохраняется в `quarantine/` и может быть начат заново. Нечитаемый или усечённый журнал, по которому нельзя доказать отсутствие мутации, даёт `INCOMPLETE_RUN` и не запускает повторную мутацию.

Привязка fixture публикуется переименованием каталога, в котором `bind.json` уже записан. Каталог без `bind.json` и привязка прогона без durable intent освобождаются. Привязка прогона, где мутация уже могла быть отправлена, не снимается.

Ответ HTTP 200 на уже существующий объект не является доказательством создания. Для PASS этой операции нужен ответ 201.

Идентификация browser при cancel сверяет случайный nonce аргумента процесса, а не подстроку пути прогона.
